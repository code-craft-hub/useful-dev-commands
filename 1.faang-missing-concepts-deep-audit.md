## 1. 🔴 CRITICAL — TESTING INFRASTRUCTURE
## ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The original structure had test files but no **testing infrastructure layer** — the plumbing that makes tests consistent and reliable across all modules.

```
src/
│
└── __mocks__/                              # ← MISSING ENTIRELY
    ├── msw/                                # Mock Service Worker — THE testing standard at FAANG
    │   ├── handlers/
    │   │   ├── users.handlers.ts           # Request interceptors for user API
    │   │   ├── products.handlers.ts
    │   │   └── index.ts                    # Combines all handlers
    │   ├── browser.ts                      # setupWorker() for browser/Storybook
    │   ├── server.ts                       # setupServer() for vitest/jest (Node)
    │   └── utils/
    │       ├── msw.utils.ts                # createMockUser(), createMockProduct() factory fns
    │       └── msw.fixtures.ts             # Realistic seed data (50+ records, edge cases)
    │
    └── next/
        ├── navigation.ts                   # Mock next/navigation (useRouter, usePathname)
        └── image.ts                        # Mock next/image

tests/                                      # ← MISSING — Root-level test infrastructure
│
├── setup/
│   ├── vitest.setup.ts                     # Global test setup (extend matchers, MSW lifecycle)
│   ├── jest-dom.setup.ts                   # @testing-library/jest-dom custom matchers
│   └── global-mocks.ts                     # window, IntersectionObserver, ResizeObserver mocks
│
├── fixtures/                               # Shared data factories (faker.js or @anatine/zod-mock)
│   ├── user.fixture.ts                     # buildUser(), buildUserList(count)
│   └── product.fixture.ts                  # buildProduct(), buildProductList(count)
│
├── helpers/
│   ├── render.tsx                          # Custom renderWithProviders() — wraps ALL providers
│   ├── query.helpers.ts                    # createTestQueryClient(), wrapInQueryClient()
│   └── router.helpers.ts                   # createMockRouter(), mockUseRouter()
│
└── e2e/                                    # Playwright E2E root
    ├── fixtures/
    │   ├── auth.fixture.ts                 # Playwright authenticated session fixture
    │   └── api.fixture.ts                  # API mocking for E2E
    ├── pages/                              # POM — Page Object Models
    │   ├── users/
    │   │   ├── UserListPage.ts             # Encapsulates user list page interactions
    │   │   └── UserDetailPage.ts
    │   └── products/
    │       └── ProductListPage.ts
    ├── specs/                              # Actual E2E test files
    │   ├── users/
    │   │   ├── user-crud.spec.ts
    │   │   └── user-auth-guard.spec.ts
    │   └── products/
    │       └── product-crud.spec.ts
    └── utils/
        ├── auth.utils.ts                   # E2E login helpers
        └── db.utils.ts                     # Test database seeding/cleanup via API
```

**Why FAANG cares:** PR reviewers will ask "how do I run this locally without hitting prod API?" MSW is the industry standard answer — it intercepts HTTP at the network level. No MSW = no reliable tests.
